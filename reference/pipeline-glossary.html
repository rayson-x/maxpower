规划链路Planning

术语含义
策略集（Strategy Set）编排知识库：分化模板、课内三层架构、各级课表、进阶模型。每条带标签（A/B 证据 · C 课程资料 · P 方案先例 · D 产品默认 · U 未知）
Composer / 组装器把"目标+经验+天数+器械"变成课表的确定性模块：周量目标 → 分化轮转 → 完整推荐+时长估算 → 逐动作安排
分化轮转练完一圈的肌群组合单元（全身/上下肢/PPL/三分化轮转），不是星期表；周量按真实轮转节奏换算
周量账本每肌群每周直接组数（weeklyDirectSets），随计划可见可断言
Proposal / 提案计划永远是先提案后确认；托管模式自动生效但可撤销（24h undo）
PlanTrace规划的推理链 artifact：输入钉、逐 slot 推理、约束事件、周量账本、逐项 diff。无 trace 不提交
PlanRevision不可变的计划版本；变更只产生新版本，planned/performed/observed 互不覆盖
RIR 区间校准 4-5（无历史）/ 工作 2-4（有历史）；标量只是兼容中点，区间才是权威
校准阶梯试重分支：RIR≥6 上调一档、4-5 接受、≤3 降档，最多 3 次试做
双进阶先加次数到上界、连续两次、再加最小器材档（≤10%）

追踪链路Tracing

术语含义
traceId一次行动的 id（= runId）：一次对话、一次规划、一次重排
sessionId长会话 id；跨多次行动
TraceEnvelope统一事件模型：kind 闭集（turn/llm/tool/guardrail/evaluator/plan/recipe/sync/error）+ 决策码 + 引用；元数据 only
双写 sink本地 JSONL（debug 开关）+ 远程适配器（CloudWatch/SLS/OTLP，配置可换）
reconcile启动时从账本投影幂等回填崩溃窗口丢失的事件
outbox账本内离线队列：恢复后补发，eventId 去重（at-least-once）
错误短码traceId 前 8 位 + sessionId 前 4 位；报错时复制即可定位全链
dotted_order / orderKey嵌套事件的稳定排序键

三种动作形态Agent Actions

形态例子确认门槛
① 代为操作"帮我记录吃了X""把卧推换成上斜"mandate 内执行（协作模式确认一次）
② 主动提案休息过短的下一组建议、趋势异常调整必须用户同意才应用
③ 场景升级"状态没变化" → 触发重排进规划模式提案照旧确认
三条铁律 planned / performed / observed 永不互相覆盖 · 任何变更可补偿式撤销 · 每份计划钉住当时规则版本
