# 目标按期达成预测：不同训练目标的可计算模型、证据边界与产品规则

> 调研日期：2026-08-13  
> 范围：健康成人的训练与体成分目标。本文讨论的是**内部的计划可达性预测**，不是疾病诊断、医疗风险评分或对用户展示的“成功率承诺”。  
> 来源限制：官方 NIH/NIDDK 材料、PubMed 收录的原始研究与系统综述/Meta 分析。  
> 结论先行：应计算的是在目标日期内、维持该目标所要求的保护约束下的条件概率，而不是由某个“放纵/未放纵”关键词触发的固定补偿。没有经本产品历史结局校准的模型时，系统只能产生内部的**风险分层**，不能把数值称为真实成功概率。

## 1. 决策问题：不是“该不该补偿”，而是“在原目标合同下还能否成立”

每份计划应先形成一个不可被日常对话悄悄改写的目标合同：

```text
目标向量 G（结果 + 保护目标）
× 截止日期 D
× 用户可接受的执行强度/风险偏好
× 安全与现实约束
```

一次聚餐、缺训或睡眠变差先成为带来源的事实，随后才进入预测。需要触发 Planner 的条件不是“用户提到放纵”，而是：基于新事实重新模拟后，达成 `G` 的条件可达性低于该合同的内部阈值，或保护约束已不能满足。

对于目标模式 `m`，推荐定义：

\[
p_m = \Pr\{G_m(X_D) \land C_m(X_{0:D}, A_{0:D})\mid \mathcal D_t, \Pi\}
\]

- `X_t`：个体在 t 日的隐状态，例如体重、脂肪/无脂组织、训练表现、疲劳与可执行时间；它不是只取一次体脂秤的读数。
- `A_{0:D}`：实际执行的摄入、日常活动、有氧和阻力训练，而非纸面计划。
- `Π`：当前候选计划。
- `G_m`：此目标模式的结果条件；`C_m`：保护条件（例如保肌、可恢复、可用时间、安全暂停）。
- `𝒟_t`：截至当前的带来源、带测量方式和时间戳的数据。

实现上以 Monte Carlo/粒子模拟估计：从个体参数后验分布取样，滚动执行动态模型直到 D，再统计同时满足目标和保护条件的样本比例：

\[
\hat p_m=\frac{1}{N}\sum_{i=1}^{N}\mathbf 1\{G_m(X_D^{(i)})\land C_m(X_{0:D}^{(i)},A_{0:D}^{(i)})\}
\]

这条式子是**产品建模设计**，不是某一篇研究验证过的通用个人成功率公式。证据支持“能量变化、剂量和测量误差必须进入模型”，但不支持在没有本产品长期结局数据时给每个人一个可信、校准的百分比。

### 为什么不能用 `7700 kcal = 1 kg` 直线外推

Hall 的动态人体模型明确模拟饮食扰动后燃料利用、能量消耗与体重/体成分的适应；其论文说明预测体重时间过程必须考虑动态能量失衡，而不是固定线性换算。[Hall 2009](https://pubmed.ncbi.nlm.nih.gov/19934407/)、[Hall 等 2011](https://stacks.cdc.gov/view/cdc/33652/cdc_33652_DS1.pdf)。NIDDK 的官方 Body Weight Planner 同时让用户输入起始条件、目标日期和活动改变，而非只用体重差除以 7700。[NIDDK Body Weight Planner](https://www.niddk.nih.gov/bwp.)

实际研究也显示 7700 规则会系统性高估减重：一项超重女性研究中，实际减重仅为该规则预测值的 44%；体成分变化和部分受试者的适应性产热解释了差异的一部分。[Westerterp 等 2010](https://pubmed.ncbi.nlm.nih.gov/20054213/)

因此，Planner 可以用能量差快速做**情景估计**，但长期达标判断必须使用动态模型并用个人趋势校准。

## 2. 共同底座：状态、输入、误差与校准

### 2.1 最小输入合同

| 输入族 | 必要字段 | 为什么进入预测 | 数据规则 |
| --- | --- | --- | --- |
| 目标 | 模式、目标值、截止日、保护目标、是否允许延期/下调 | 决定事件是否真的构成“偏离” | 没有截止日期，不能判断“按期”达成。 |
| 基线与测量 | 体重趋势、腰/围度、体脂/体成分的**方法与误差**、主要动作表现 | 同一目标在不同测量方法下不是同一观测量 | 仅比较同方法、相近测量条件的连续数据。 |
| 实际摄入与活动 | 每日/餐食记录完整度、计划外摄入范围、步数/活动、训练完成度 | “计划热量”不能代替实际能量输入与执行 | 区分测量值、用户估计和模型推断。 |
| 训练剂量与质量 | 每肌群实际直接/间接工作组、负荷/次数/RIR、动作条件、训练日程、疼痛/停止信号 | 训练计划是否执行以及刺激是否可比，决定保肌、肌肥大和力量预测 | 不由 LLM 伪造 RIR、重量或完成组数。 |
| 个人历史 | 至少 2–4 周可比趋势（视目标时间尺度）、既往依从性、恢复与日程限制 | 把群体先验替换为个人后验 | 数据不足时扩大不确定度，不制造精度。 |

`食物热效应` 可作为能量消耗模型的一个成分，但不能在日志不完整时被当作“确定可补回的热量”。动态能量模型应把宏量、体成分、体重和活动改变作为状态演化的一部分；NIDDK 的模型也把体重、活动与目标日期联动，而不是将每一餐的热效应独立、精确地抵销。[Hall 2009](https://pubmed.ncbi.nlm.nih.gov/19934407/)、[NIDDK Body Weight Planner](https://www.niddk.nih.gov/bwp.)

### 2.2 个体化参数：先验 → 校准后验

令：

```text
θ = {维护能量与其漂移、摄入记录偏差、活动执行率、训练完成率、
     体重/体成分分配、力量/肌肥大响应、测量误差、恢复导致的可执行性}
```

初始化时可按照性别、体重、身高、体脂估计、训练状态和目标类型使用宽的群体先验；每次有合格的连续趋势便更新 `p(θ | 𝒟_t)`。不应把“天生响应者”“纤维类型”当作预先可得的解释：训练反应的个体差异很大，而一个 10 周新手研究中，肌肉类型不能解释肌肉体积、力量和肌纤维横截面反应的这种变异。[Delrue 等 2023](https://pubmed.ncbi.nlm.nih.gov/37038845/)

推荐用两个独立的执行概率，而不是一个泛化的“自律分”：

\[
q_{diet}=\Pr(\text{未来摄入落在计划容差内}\mid \text{近期记录与事件})
\]
\[
q_{train}=\Pr(\text{未来关键训练/活动完成}\mid \text{近期完成度、日历与恢复})
\]

它们是产品预测参数，不是人格评分；需允许用户修正，并把置信区间随数据缺失扩大。实际观测（完成、取消、摄入范围、体重趋势）比“我会努力”的文本更应影响后验。

### 2.3 执行失败率与连续性：不是简单的打卡计数

“总摄入量”和“训练打卡成功次数”都必须进入预测，但不能用
`打卡次数 / 计划次数` 取代执行判断。Planner 应同时保留：

```text
energyPathRatio = 实际累计净能量缺口 / 计划累计净能量缺口
q_diet          = 未来一天落在约定摄入容差内的后验概率
q_train         = 未来关键训练达到最低有效剂量的后验概率
coverage        = 所需摄入、训练与测量事实的记录覆盖率
recentFailureRun = 连续确认失败的关键行动数
weightedFailureRate = 带近期性与关键性权重的窗口失败率
executionSlope  = 执行率正在改善、持平或恶化的趋势
```

对窗口内每一个**确认过**的饮食日或计划训练，存 `0..1` 的执行贡献 `z` 和
权重 `w`（近期性、数据置信度、目标关键性）。保守初版可估计：

\[
q=\frac{\alpha+\sum(wz)}{\alpha+\beta+\sum w}
\]

饮食的 `z` 来自报告摄入区间相对计划容差；训练的 `z` 来自关键课表完成及
最低有效剂量，不能仅因点击“完成”而满分。**确认缺训**可以 `z=0`；没有记录
不能自动当失败，只降低 `coverage`、扩大不确定度，必要时输出
`insufficient_evidence`。

连续性必须额外进入模型：两次相隔六周的非关键漏训，与连续两次漏掉短期目标
中的关键训练，不能产生相同结论。初版可以构造用于更新未来执行分布的压力项：

```text
failurePressure = weightedFailureRate
                  + modeWeight × recentFailureRun × criticality
                  + deteriorationWeight × max(0, -executionSlope)
```

它不是全人群固定阈值。阈值由剩余缓冲、截止日和目标保护条件决定：极限体脂/
保肌或力量保留目标的缓冲更小；周期更长、体脂储备更大的减脂目标可吸收同一
事件。连续失败或高且恶化的失败率只要实质性降低剩余路径的可执行性，就应触发
`at_risk` 和候选修正搜索，即使体重趋势尚未显现；单次失败而仍有缓冲则无需
自动改计划。

### 2.4 体重和围度长期无变化：先判定证据，再判定平台期

“体重长时间没变、围度也没变”是强的计划信号，但不是自动证明代谢平台期。
必须用同一测量协议、目标模式对应的观察窗口和测量误差模型，先判断零趋势是否
可与噪声区分：

\[
P(|\beta_{weight}|<\delta_{weight}\ \land\ |\beta_{girth}|<\delta_{girth}
\mid \text{可比观测、测量误差})
\]

这里 `β` 是趋势而非单日差，`δ` 是方法、目标和时间窗口相符的最小有意义变化。
因此不存在全产品的“体重两周不动就是平台期”规则。

在联合趋势确实接近零后，Planner 以执行证据进行分流：

| 证据组合 | 不能/可以得出的结论 | 后续动作 |
| --- | --- | --- |
| 体重平但腰围/目标围度下降 | 不能称为联合平台；可能有水分掩盖或体成分变化 | 保持计划和测量协议，解释指标冲突。 |
| 日志覆盖低、摄入范围不确定、`q_diet/q_train` 下滑或能量路径偏离 | 不能判定生理平台，只能判定执行/观察不足 | 记录已知事实，提出最小的记录或测量改进；不能以额外有氧/更低摄入惩罚不确定性。 |
| 覆盖高、饮食与关键训练持续达标、测量可比、体重和围度联合平稳 | 可标为 `candidate_response_plateau`，可能包含未建模的活动补偿、能量适应或响应差异 | 重新预测剩余路径；若进入 `at_risk`，给一个最小干扰、安全的未来调整实验供确认。 |
| 联合平稳且恢复/表现持续下降 | 更可能是不可持续风险，而不是应当继续加码的“平台” | 先重评恢复、训练剂量和保护约束，禁止自动强化。 |

平台期提案必须是可验证的单变量实验：固定训练结构和测量条件，只改变一个经
用户确认的摄入或活动杠杆；预先定义观察期限、趋势信号与停止条件。若该信号
未改变，更新个人模型或重新协商目标，不能不断叠加限制。

### 2.3 测量误差先于“进展判断”

目标预测必须携带观测误差；否则一次水分、测试条件或设备变化会被误判为计划失败。对抗阻训练者的连续日 DXA 测试中，脂肪量和瘦体重的精密度误差分别约 1.261 kg 与 2.083 kg，明显高于同日重复扫描，因此纵向解释需要最小显著变化而非读数差本身。[Toombs 等 2018](https://pubmed.ncbi.nlm.nih.gov/30454952/)

消费级智能秤的体重误差很小，但体脂和“肌肉量”的个体绝对误差可达数公斤，不能作为个人体脂目标是否达成的唯一证据。[Frija-Masson 等 2021](https://pubmed.ncbi.nlm.nih.gov/33929337/)

**产品规则（推导）**：为每个指标存 `method`、`same-device`、`standardisation`、`SEM/LOA 或来源默认误差`。当目标剩余变化小于该指标的最小显著变化时，降低达成判断的置信度、延长观察窗口或要求第二个独立指标；不要通过加大训练/缺口来“纠正”噪声。

## 3. 一个可实现的内部预测框架

### 3.1 每日状态转移

使用按目标模式选择的动态转移：

\[
X_{t+1}=f_m(X_t, I_t, E_t, R_t,\theta_m)+\epsilon_t
\]

- `I_t`：摄入的区间/分布，而非单点卡路里；包含未记录餐和聚餐估计的不确定度。
- `E_t`：基础与非运动活动、训练和有氧引起的能量支出；随体重和实际活动更新。
- `R_t`：实际阻力训练剂量、表现与恢复可行性；不是“排了四天”即默认为完成四天。
- `ε_t`：水/糖原、测量、行为和模型残差。

每次新事件只重算未来日期；不能把未来计划重新排得更严就假设 `q_diet` 或 `q_train` 自动上升。若一个“补偿方案”让可执行概率下降，模拟中它可能反而降低按期达成的总体概率。

### 3.2 决策输出：内部状态，而非向用户报百分比

将 `p_m` 与数据质量、保护约束合并为内部状态：

| 内部状态 | 条件 | 主 Agent 行为 |
| --- | --- | --- |
| `on_path` | 目标与保护约束在多数模拟中成立，且数据足以辨别趋势 | 记录、解释、保持计划。 |
| `at_risk` | 目标边缘、事件消耗缓冲，或数据不确定度使判断不稳 | 主动向 Planner 请求安全的候选修正；说明“为了尽量守住原截止日”，不展示概率。 |
| `infeasible_under_guardrails` | 在用户声明的最大可执行强度和保护约束内，目标模拟无法成立 | 明确给出取舍：缩短/提高执行强度、延后日期、降低目标，或补数据；不得暗中延后。 |
| `insufficient_evidence` | 基线、测量一致性或实际执行数据不足 | 最多追问三项会显著缩窄不确定度的信息；先生成保守探索版。 |

`at_risk` 的门槛应在产品结局数据上校准，且按目标模式不同；没有校准数据时只用保守的规则性门槛，并明确标为产品假设。绝不可把它说成医学或科学意义上的成功率。

### 3.3 候选修正的选择

Planner 比较 `Π_current` 与候选 `Π_j`，优先选择满足保护约束且内部可达性最高的候选：

\[
\Pi^*=\arg\max_{\Pi_j}\left[\hat p_m(\Pi_j)-\lambda_B B(\Pi_j)-\lambda_R\operatorname{Risk}(\Pi_j)\right]
\]

`B` 是新增时间、饥饿/恢复负担和日程冲突；`Risk` 是安全、过度限制、疼痛/异常症状与恢复冲突。`λ` 来自用户事先选择的执行档位，**不能**由一次放纵自动改写。此优化式是产品决策设计，不代表临床上已验证的个体最优处方。

## 4. 模式不同，目标函数和硬约束不同

### A. 增肌 / 肌肥大

**结果条件**：在截止日，主要目标肌群的同方法尺寸/瘦体重代理超过最小显著变化；并且训练可持续。体重上涨不是肌肥大本身，不能单独充当成功指标。

**状态与模型输入**：目标肌群的围度/影像或标准化体成分趋势、训练状态、实际的直接/间接工作组、动作可比性、负荷/次数/RIR、完成率、摄入/蛋白记录、恢复与可用时间。

**证据能支持的先验**：周训练量与肌肉量增长存在剂量–反应关系，但该 Meta 分析只含 15 项研究/34 个处理组；它支持把实际每周组数作为预测变量，**不支持**为某人承诺每加一组必长固定多少肌肉。[Schoenfeld 等 2017](https://pubmed.ncbi.nlm.nih.gov/27433992/)

蛋白补充与阻力训练的 Meta 分析显示，在健康成人中可增加无脂/瘦体重与力量增益，且效应受年龄、训练状况和总蛋白摄入影响；因此蛋白/能量可作为不确定的响应变量，不是单一“达标按钮”。[Morton 等 2018](https://pubmed.ncbi.nlm.nih.gov/28698222/)

**保护条件**：不以不能恢复的加组/加频率换取模型分数；若摄入处于长期明显能量缺口，不能同时预测正常的肌肥大。能量缺口下的抗阻训练 Meta 回归发现，无脂体重增益受损，约 500 kcal/日缺口与无脂体重增长被阻断相关；这是群体关系，不是对每人的硬阈值。[Murphy & Koehler 2022](https://pubmed.ncbi.nlm.nih.gov/34623696/)

**预测公式重点**：以 `Δmuscle_target` 的后验分布为主；训练剂量、完成率、能量状态和测量误差进入模型。若只有体重，输出应为“体重增重轨迹”，不得命名为“增肌达成”。

### B. 大重量 / 最大力量

**结果条件**：在规定测试条件下（动作、ROM、器材、暂停/触胸规则等不变）目标 1RM 或预先定义的 e1RM 置信区间达到目标；任何技术或器材变化要分开建模。

**状态与模型输入**：目标动作近几次可比的负荷、次数、RIR 或速度（如有）、测试条件、实际专项直接工作组与相对负荷、疲劳/完成率。

**证据能支持的先验**：抗阻剂量–反应的综合 Meta 分析纳入 295 项研究、6,710 人，发现结果域与负荷强度、训练时长和组数相关，最大力量的最优负荷曲线与跳跃/功率不同，较重负荷更有利于最大力量。[Swinton 等 2024](https://pubmed.ncbi.nlm.nih.gov/38652410/)

但群体效应并不能给单个训练者一个精确的“下月卧推 +x kg”公式。应以个人过去至少数次同条件暴露后的表现趋势为主要后验；基线低、技术学习空间大和测试不一致时，预测区间应更宽。

**保护条件**：不得为追求目标 1RM 将恢复、动作疼痛/停止信号、必要技术练习或现实日程视为可忽略项；不能用体重上升替代专项力量证据。

### C. 减脂：总体体重/脂肪量为主（“大体重减脂”）

**结果条件**：按期达到目标体重/脂肪量区间，同时遵守最低能量、恢复和安全限制。这里预测的是目标区间，不是每日秤重的单点。

**状态与模型输入**：体重的滚动趋势、体成分/腰围的同方法趋势、动态能量模型状态、饮食完整度与偏差范围、NEAT/步数和有氧/阻力训练实际完成度。

**证据能支持的先验**：更高的基线脂肪量与更大的脂肪量变化在抗阻研究中有关联，但效应和个体差异仍大；抗阻训练加能量限制可改善脂肪量变化，且通常比限制饮食而不抗阻更能维持瘦体重。[Lopez 等 2022](https://pubmed.ncbi.nlm.nih.gov/35977113/)、[Lopez 等 2022（综述）](https://pubmed.ncbi.nlm.nih.gov/35191588/)

**产品区分**：所谓“大体重”不可仅由体重绝对值定义；进入先验/安全规则的应是体脂或脂肪量、无脂体重、既往减重/饮食史、训练状态、健康筛查与可用时间。资料不全时不要因为“体重较大”自动允许更严的未来补偿。

### D. 减脂且保肌（更瘦、已有抗阻训练者的“低体重减脂”）

**结果条件**：达到脂肪/腰围目标，且无脂体重的变化不越过测量方法的最小显著变化与预先定义的表现保护条件；`体重下降` 不等于成功。

**核心区别**：同一能量缺口，在瘦且已训练人群里，保留无脂体重和表现比“秤重速度”更重要。精英运动员 RCT 比较每周约 0.7% 和 1.4% 体重下降，两组均做每周四次抗阻；研究目的即检验更慢减重能否更好维持无脂体重和力量/功率，说明速度与保肌/表现必须共同进入目标函数，而不是只按缺口最大化。[Garthe 等 2011](https://pubmed.ncbi.nlm.nih.gov/21558571/)

在一个特定但高强度的 4 周 RCT 中，年轻男性在约 40% 能量限制并进行每周六天阻力/间歇训练时，2.4 g/kg/d 蛋白组的无脂体重和脂肪量结果优于 1.2 g/kg/d 蛋白组；这支持“蛋白和训练质量影响体成分分配”，不能外推为所有用户的自动配方或安全上限。[Longland 等 2016](https://pubmed.ncbi.nlm.nih.gov/26817506/)

**保护条件**：保肌模式在模拟中必须同时通过：

```text
脂肪目标趋势  AND
无脂体重变化超过测量噪声的风险可接受  AND
主要动作表现/训练质量未出现持续恶化  AND
恢复、饮食与安全约束可持续
```

若想通过增加有氧或减少摄入追回日期，系统必须重估这四项，而不是只看预计多消耗的卡路里。已有 Meta 分析显示能量缺乏会损害无脂体重增长，而力量变化未必同方向，因此不能用“力量没掉”证明“没有丢瘦体重”。[Murphy & Koehler 2022](https://pubmed.ncbi.nlm.nih.gov/34623696/)

### E. 塑形 / 体态审美

**结果条件**：一个多目标向量，而非“审美评分”：

```text
fat/waist proxy + 目标围度或比值 + 目标肌群的可比表现/训练量 +
标准化照片或用户主观满意度
```

例如“宽肩窄腰”可以以肩围、腰围、上肢目标肌群的可比刺激/围度趋势，以及同姿势/光线的照片为代理；“清晰腹肌”不能被合法地从一次 BIA 体脂读数推出。审美偏好本身应由用户定义并允许随时编辑，系统不应把它伪装成医学目标。

**误差规则**：围度要固定测量位置、姿势、时间和工具；对 3D 扫描，重复测量可很可靠，但这不意味着不同设备或不同姿势可混用。[Wang 等 2010](https://pubmed.ncbi.nlm.nih.gov/20833990/)。若用智能秤/BIA，只作为同设备趋势的弱证据，不能以其绝对体脂判定“腹肌何时可见”。[Frija-Masson 等 2021](https://pubmed.ncbi.nlm.nih.gov/33929337/)

**预测公式重点**：对每个代理输出独立的“目标窗口内趋势是否足够”概率/风险，再用 `AND` 或用户指定权重汇总；绝不训练一个没有验证数据集的视觉“好身材/腹肌可见”分类器后就给出确定性时间。

## 5. 执行档位：用户意愿是模型参数，不是事后免责

建议 Goal Contract 明确选择一个不可隐式升级的档位：

| 档位 | 含义 | 对模型的影响 |
| --- | --- | --- |
| `protect_deadline` | 优先守住目标日期；仍受安全/恢复上限限制 | 在事件后搜索饮食、活动、训练排程的安全候选，主动生成待确认提案。 |
| `balanced` | 平衡日期、训练质量和生活弹性 | 更早把“缓冲耗尽”标为 at risk，偏好小幅、可持续修正。 |
| `protect_sustainability` | 允许较慢进度，优先可持续与保肌/恢复 | 降低对短期偏差的修正强度；**必须由用户明确同意**改变截止日或结果目标。 |

“4 周减脂 4%”与“8 周减脂 4%”是两份不同合同。前者在一次额外能量摄入后可能触发 `at_risk`，Planner 应主动提出如何在原日期内提高可达性；后者不能由系统默认为同样严格。无论档位是什么，若没有安全候选，输出必须是明确的取舍，不是隐性延期或极端补偿。

## 6. 不可自动跨越的安全与准确性边界

1. **预测不等于保证或诊断。** “成功概率”必须只在模型经过预注册、留出集校准和持续漂移监测后才可能作为内部量表；用户界面显示理由、取舍和下一步，不显示未经校准的百分比。
2. **不得为恢复一夜之间把执行率设为 100%。** 候选计划的额外训练/有氧、摄入收紧和时间成本必须反过来影响 `q_diet/q_train`；否则优化器会偏好不可执行的方案。
3. **不得把训练消耗当作精准结算。** 可穿戴设备、活动消耗和食物日志都有误差；用体重/围度的多日趋势校准，而非让用户以“多吃 x → 必须跑 y 分钟”接近假精度。
4. **减脂和增肌的保护条件不能互换。** 有长期显著能量缺口时，不能给“正常增肌”高置信预测；保肌减脂需追踪体成分和表现，不能只盯体重。[Murphy & Koehler 2022](https://pubmed.ncbi.nlm.nih.gov/34623696/)
5. **资料不足时做最小实验。** 固定训练与测量条件，只改变一个可执行变量（如平均能量输入或非训练日步数），连续观察足以越过测量误差的窗口；成功/失败信号预先定义为趋势和完成度，而非单日秤重。NIDDK 对其能量模型的官方说明也强调以连续体重数据推断能量摄入变化，并在 CALERIE 数据中做过验证。[NIDDK 研究说明](https://www.niddk.nih.gov/news/archive/2015/model-counts-calories-tracking-body-weight)
6. **遇到症状/既有医学限制则停止自动加压。** 这套系统只对完成健康筛查、无需要医疗处理信号的用户做一般计划；应转入安全暂停与人工/专业支持流程，而非用预测引擎加大训练或限制。

## 7. 推荐的落地顺序与可验证实验

### P0：先实现“可校准的达标风险”，不是“精准成功率”

1. 为 Goal Contract 增加 `targetMode`、`deadline`、`guardrails`、`executionTier`、`measurementPlan` 与 `slowdownConsent`。
2. 为每个输入保留来源与不确定度；实现体重/围度趋势和动态能量模型，禁用 7700 直线作为长期裁决。
3. 使用 `on_path / at_risk / infeasible_under_guardrails / insufficient_evidence` 四态；由主 Agent 根据此状态主动调用 Planner，而非从“放纵”词语直接触发补偿工具。
4. 只允许 Planner 输出未来计划预览；确认前不更改正式计划；确认时用最新事实重算。

### P1：目标模式的专用预测器

- **力量**：先对单一动作的同条件 e1RM/表现做趋势预测；收集足够暴露次数后再拟合个体随机斜率。
- **保肌减脂**：将体重、腰围、同方法体成分、关键表现和实际训练完成率联合建模；任何一项证据低质都会扩宽区间。
- **增肌/塑形**：先落实同方法围度/照片协议和最小显著变化，再开始评价“可见改变”；不要以体重代理肌肉量。

### P2：产品级校准与回测

将过去已结束目标按模式、训练状态、测量方法与档位切分。对每次预测保留 `predicted band / state / outcome`；仅在留出用户与留出时间段上检验：

```text
校准：预测 60% 的分桶中，约 60% 真正达成；
区分度：at_risk 的未按期率高于 on_path；
安全：提案没有系统性提高疼痛、掉训或极端限制事件；
公平性：误差不因性别、基线体脂、设备/记录完整度而系统失衡。
```

没有这些回测时，最诚实的产品措辞是“系统判断当前计划需要调整以尽量守住你的目标日期”，而不是“你的成功率是 72%”。

## 8. 对 Agent Harness 的直接含义

首页 Agent 应获得一个深 Module，例如：

```ts
planner.assessAchievability({
  goalContract,
  factualSnapshot,
  planningOptions,
}): AchievabilityAssessment
```

它不由 Agent 关键词路由，也不直接写计划。输出包含：内部状态、关键驱动因素、数据缺口、候选修正和验证报告。主 Agent 在工具说明中被要求：当用户报告的新事实可能改变目标合同的按期可达性时，调用该 Module；得到 `at_risk` 后主动解释并展示待确认修正；得到 `insufficient_evidence` 时至多追问三项真正改变结论的数据。

这个 Interface 保持小，而把动态能量模拟、个人后验、模式特异目标、剂量/恢复验证和校准 trace 都隐藏在 Planner Harness 的 Implementation 内部。这样既让 Agent 有语义判断权，也不会让 LLM 负责心算、虚构事实或绕过正式计划确认。
