# 斜侧机位下相对高度与动作阶段理解：文献调研和本地验证

日期：2026-08-13

## 结论先行

**现阶段不需要先把 45° 视频重建成真实 3D，也不需要把画面“转正面”。** 对预设动作、预设机位的卧推，单目 2D 已经足以支持以下能力：

- 杠铃进入离心、到达换向点、进入向心、返回起点；
- 每个 Rep 的相对行程、阶段耗时、组内行程下降和回程不完整；
- 在同一机位和同一组内比较轨迹重复性；
- 将器械轨迹与腕、肘、肩等骨架轨迹融合，降低单一骨架点抖动或遮挡的影响。

原因是这些判断依赖的是**时序、方向变化和归一化相对位移**，不依赖实验室级的绝对摄像机高度或精确相机外参。

但当前不能把 2D 像素直接解释为：

- 真实世界的厘米高度、三维速度或三维杠铃路径；
- 斜侧机位里两端画面 `y` 坐标的差值等于真实左右高低差；
- 用户满足统一的“标准动作轨迹”；
- 力量、关节力矩、肌肉激活或真实左右发力大小。

换句话说：**换向点和相对阶段理解已经有很强的本地可行性证据；任意机位泛化与动作质量标准尚未完成验证。**

## 该用什么转换逻辑

不建议用画面的竖直方向作为固定“高度轴”，也不建议先把视频透视变换成正面。建议每次 Set 建立一个局部运动坐标：

1. 跟踪杠铃中心 `p(t)`、两端点和相关骨架点。
2. 用短时间窗口内杠铃中心的主运动方向，估计该机位中的器械运动轴 `u_motion`。
3. 将位移投影到该运动轴：

   `h(t) = dot(p(t) - p_ref, u_motion) / scale`

4. `scale` 使用可见杠长、肩宽、躯干尺度或本组稳定 Rep 的行程，使其成为无量纲相对高度。
5. 使用平滑后的 `h(t)`、速度符号变化和最小持续时间识别离心、换向、向心和返回。
6. 骨架不是用来覆盖器械信号，而是共同判断：腕部是否随杠、肘角是否同步变化、躯干与支撑点是否稳定。

这一表达对以下变化天然更稳健：

- 画面整体平移：`p(t) - p_ref` 会消除平移；
- 手机轻微旋转：运动轴随画面一起旋转；
- 拍摄距离变化：归一化尺度会抵消统一缩放；
- 左前 45° 和右前 45°：使用各自的机位语义和镜像映射，不要求原始轨迹水平。

它不能完全消除明显的俯拍/仰拍、过大的透视变化和出平面运动。因此相机高度不必精确，但产品仍应约束在一个可接受机位范围内，并在每个 Set 重新估计局部坐标和观测可信度。

## 网上资料给出的边界

### 1. 单摄像机确实可以测到 Rep、位移和速度

Taber 等人用手机视频系统和 3D 动捕同时测量卧推、深蹲和硬拉。视频系统的杠铃位移与 3D 动捕相关性为 `r=0.43–0.94`，可靠性为 `ICC=0.67–0.98`，位移偏差小于 2 cm；平均速度相关性为 `r=0.67–0.95`。这证明单摄像机轨迹并非只能“看动画”，在受控条件下可以形成有效运动量。[原始论文](https://doi.org/10.47206/ijsc.v3i1.263)

### 2. 角度偏离不会立刻让 Rep 识别失效，但会降低几何量准确度

Trowell 等人把手机分别放在相对最佳位置 `-20°、-10°、0°、+10°、+20°`，应用在深蹲和卧推中总体识别了超过 95% 的 Rep。可是相机离最佳角度越远，ROM 和速度的偏差/一致性范围通常越差；卧推在重重量慢速 Rep 下还出现漏检。这正好支持本项目的分层结论：**阶段和换向比绝对 ROM/速度更容易对机位保持鲁棒。** [PeerJ 原始论文](https://peerj.com/articles/17789/)

### 3. 真实健身房里，杠铃倾斜、相机畸变和出平面路径都会造成误差

Renner 等人的 Vicon 对照研究说明，手机应用可以达到线性位移传感器级别的平均向心速度，但不同应用差异很大。论文明确指出杠铃倾斜、相机畸变、冠状面运动、分辨率和帧率会影响准确度。其有效实验仍使用了约 1 m 高、距杠铃约 3 m、居中、侧拍和已知尺寸杠铃片等标准化条件。[PLOS ONE 原始论文](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0313919)

### 4. 骨架遮挡侧不能被当成与可见侧同等可靠

单目 2D 无标记姿态研究发现，被遮挡侧髋膝角度的偏差离散程度和一致性界限约为相机可见侧的两倍。因而斜侧卧推应当保留逐点置信度，并允许器械时序帮助约束腕肘轨迹，而不是把低置信度骨架点画成确定事实。[原始研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC10635560/)

### 5. 为什么不直接声称“真实高度”

针孔相机把三维点投影到二维图像；没有相机内参、外参、已知尺度或多视角时，一个二维点没有唯一的三维深度解。平面单应变换只对同一物理平面或纯旋转等受限情形成立，不能把一般的卧推三维运动无损“转正”。[OpenCV 相机模型](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)；[OpenCV 单应性说明](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html)

## 本地数据治理边界

本轮首先在 `maxpower-training-data-governance` 运行了 `npm run audit`，24 个登记资产审计通过。

本地使用范围如下：

| 资产 | 状态 | 本轮用途 |
|---|---|---|
| `personal-human-rep-ranges-v2` | `label_allowed` | 只使用动作、机位、计数和人工起止范围 |
| `personal-native-rtmpose-halpe26-observations` | `feature_only` | 使用客户端可运行的 Halpe-26 观测作为特征 |
| `barbell-geometry-alignment-prototype` | `proposal_only` | 只做器械轨迹可观测性和失败诊断，不作为已接受真值 |

当前治理资产里没有人工逐帧杠铃端点真值，也没有已接纳的动作质量真值。因此本轮可以验证“相对高度信号和换向阶段是否可观测”，不能验证“检测框每一帧有多准”或“动作是否标准”。

## 本地测试 A：相对高度信号是否真的可观测

### 方法

- 视频：6 条个人杠铃卧推，共 46 个 Rep。
- 机位：正面 16 Rep、右前 45° 25 Rep、左前 45° 5 Rep。
- 人工标签只用于提供每个 Rep 的起止区间；没有读取旧 `peakMs`、备注或动作质量结论。
- 对每个区间的 2D 杠铃中心轨迹做 PCA，取主运动轴，计算相对位移幅度、信号/抖动比、主轴占比、候选换向位置和起终点返回误差。
- 这是“区间内可观测性”测试，不是盲计次测试。

### 结果

| 机位 | Rep | 可形成稳定相对高度信号 | 中位行程/画面高度 | 中位信号/抖动比 | 主运动轴中位占比 |
|---|---:|---:|---:|---:|---:|
| 正面 | 16 | 16/16 | 12.81% | 112.7 | 99.49% |
| 右前 45° | 25 | 25/25 | 18.62% | 59.0 | 99.83% |
| 左前 45° | 5 | 5/5 | 19.12% | 141.0 | 99.38% |
| 合计 | 46 | 46/46 | 16.41% | 79.5 | 99.73% |

这说明在现有素材中，斜侧视频里的杠铃轨迹并没有因为“看起来是歪的”而失去阶段信息。沿实际运动主轴投影后，46 个 Rep 都存在明显且连续的相对高度变化。

但是这项 46/46 不能叫“识别准确率”：

- Rep 区间是人工提供的，算法没有在这里盲找区间；
- 可观测阈值是探索性阈值，并非预注册验收门槛；
- 器械轴尚无人工逐帧几何真值；
- 现有机位画面整体较正，主运动轴距图像竖直中位数只有约 1.42°，尚未覆盖明显手机倾斜。

## 本地测试 B：客户端真实链路的单次因果阶段识别

现有冻结报告运行的是：

`onnxruntime-web / YOLOX-nano HumanArt / RTMPose-M Halpe-26 -> Rust WASM causal barbell axis`

报告明确记录：按时间顺序单次流式处理，预测冻结后才揭示人工数据，Python 视觉模型未进入识别链路。

### 六条视频整体

- 人工确认 Rep：46；
- 高置信度输出：45，匹配 45；
- 高置信度 precision：100%；recall：97.83%；
- 换向点落在 ±250 ms 容差内：45/46 = 97.83%；
- 45 个已匹配换向点的绝对误差中位数约 33 ms，P95 约 133 ms，最大约 167 ms；
- 包含 `needs_review` 通道时，Rep 为 46/46，但最后一项换向点超出容差，不能把它算成 100% 阶段准确。

### 只看斜侧机位

- 左前/右前 45° 共 3 条视频、30 Rep；
- 计数和匹配：30/30；
- 换向点在 ±250 ms 内：30/30；
- 完整起点—换向—终点对齐：29/30；
- 换向绝对误差最大 133 ms。

这比“肉眼感觉挺准”更具体地支持了用户体验：**当前客户端链路在现有斜侧卧推素材上，确实能够稳定记录离心到向心的换向点。**

## 人工审核记录应如何解释

审核日志中，6 条视频共 46 个 Rep 的换向候选均被提交为 `human_confirmed_candidate`。这表示审核者逐 Rep 看过并接受了 Rust 候选，没有把换向时刻改成另一个值。

它是很强的产品可用性证据，但不是完全独立的盲标：审核者先看到了算法候选，可能存在锚定效应。因此应分成两层声明：

- **可以声明**：在现有 6 条视频中，用户逐 Rep 接受了 46 个候选换向点；客户端单次链路在 45 个高置信输出上达到 97.83% 的 ±250 ms 对齐，斜侧 30 个候选全部在容差内。
- **不能声明**：对新用户、新场地、任意手机高度/角度已经达到 95% 或 100% 泛化准确率。

若要形成正式换向真值，建议把审核事件登记进治理目录，并对一小部分 Rep 做不显示候选位置的盲标或随机偏移审核，量化候选提示造成的锚定偏差。

## 当前到底能理解什么

| 能力 | 当前结论 | 依据 |
|---|---|---|
| 完整 Rep 计数 | 现有卧推素材可用 | 客户端因果流 45/46 高置信；含复核通道 46/46 |
| 离心/向心换向点 | 现有素材强支持 | 整体 45/46 在 ±250 ms；斜侧 30/30 |
| 相对 ROM、提前反转、回程不完整 | 信号可观测，可进入规则引擎的候选层 | 46/46 区间内有稳定主轴位移；尚缺质量真值和阈值审核 |
| 组内轨迹漂移 | 技术上可计算 | 应在同机位、同组、归一化坐标内比较 |
| 左右端点时间差 | 技术上可计算，未验收 | 需要独立端点真值，不能用当前几何提议自证 |
| 左右真实高低 | 暂不能声称 | 斜侧透视会让远近端天然投影不同 |
| 标准动作/借力/刺激偏移 | 暂不能声称 | 目前没有已审核标准走廊和动作质量金标 |
| 厘米、真实三维路径、关节力矩 | 不支持 | 单目无标定问题本身不可辨识 |

## 下一步最小验证，不是先做完整 3D

真正需要补的是“机位扰动基准”，而不是继续重复回放当前 6 条视频。

建议冻结当前模型和 Rust 参数后，用同一个人、同一动作、同一重量做单变量实验：

1. 固定其他变量，只改变相机高度：低、中、高三档；
2. 固定其他变量，只改变水平拍摄角：约 30°、45°、60°；
3. 固定其他变量，只改变手机滚转：约 `-8°、0°、+8°`；
4. 每档至少两个新 Set，不把这些视频用于调参；
5. 每个 Rep 审核计数、起点、换向、终点；抽样盲标器械中心/两端；
6. 沿用当前门槛：计数 precision/recall、整组 exact-set、换向 ±250 ms、起终点 ±500 ms；另报各机位相对 ROM 的组内变异；
7. 若阶段仍稳定但 ROM 跨机位偏移，则保留阶段能力，把 ROM/质量比较限制在同机位或个人机位基线内；若阶段也明显下降，再考虑相机姿态估计、单目深度或多视角 3D。

## 决策建议

1. **继续使用器械轨迹 + 骨架轨迹的客户端因果融合，不需要为 MVP 先上完整 3D。**
2. Rust 中使用局部运动轴和无量纲相对高度，不使用原始画面水平线或原始 `y` 差值解释动作。
3. 当前换向点可以作为审核页面和动作阶段规则的第一版输入，因为它已有逐 Rep 用户确认和客户端单次链路证据。
4. ROM、左右稳定性和动作标准性先保持“可审核候选”，等待标准/个人走廊与独立真值。
5. 对外能力声明限定为现有一名用户、6 条已知卧推、正面/左右前 45°；完成新机位扰动冻结测试后再扩大范围。
