# 2D 骨架：姿态代理可观测性与动作相位对齐审查（2026-08-05）

## 结论先行

**技术上可行，但只能做“受约束的二维动作反馈”，当前还不能诚实地称为“自动纠正动作”。** 现有系统可以把一段已可靠封装为 `start → peak → end` 的动作归一化到共同相位，找出同动作、同机位下可见的腕/肘/肩/髋二维轨迹差异；它不能仅凭单目骨架确定“实际发力”、单块肌肉激活、负荷、真实三维关节角或被遮挡一侧的姿态。

“看见差异”和“帮助用户纠正”之间还缺两层证据：

1. **判断有效性：** 系统指出的差异是否与独立教练在同一预先定义错误上的判断一致，而不是只与用户自己的历史轨迹不同。
2. **反馈有效性：** 用户收到一条具体提示后，目标二维指标和教练盲评是否在下一组改善，并能在撤掉提示后保持；“模型输出了建议”本身不等于用户学会了动作。

视觉反馈确实有帮助动作学习的实验依据：一项 30 人随机双盲试验中，训练后视频反馈改善了初学者深蹲的若干运动学/足底压力指标，部分保持到 3 天或 1 周；但另一项 19 人的 5 周随机试验中，开放式技术反馈没有改善盲评深蹲技术，而传统口头反馈有改善。这说明产品成败不仅取决于骨架精度，还取决于**反馈目标、措辞、时机和学习迁移**，必须在本产品上单独验证。[Shin et al., 2024](https://pubmed.ncbi.nlm.nih.gov/37916599/)；[Vidal et al., 2022](https://pmc.ncbi.nlm.nih.gov/articles/PMC9438286/)

所以“是否对齐”应拆成两个问题：

1. **时间/相位对齐：可行，但必须以人工边界或已经可靠的 Rust 封装边界为锚。** 对齐不是发现动作本身；它只是把已确定的一次动作映射到相同的 32 个相位节点。
2. **姿态/发力判断：只可输出有机位支持的二维观测量与其不确定性。** 例如正面侧平举的双腕相对高度、左右肩高差、腕部横向展开、肘部投影角、两阶段时长；“三角肌是否发力充分”“负重是否合适”“肩关节真实外展角”都不能由这些数据确定。

本轮实际归档数据支持优先把**正面侧平举**和**正后高位下拉**推进为“已对齐的二维姿态代理”实验桶；正面坐姿推肩只能做条件性实验，因为顶部事件不稳；正面反向飞鸟与左后 45° 高位下拉首先要解决可观测性/丢点问题，不能直接进入轨迹质量比较。

### Go / No-Go

| 产品主张 | 当前结论 | 依据 |
| --- | --- | --- |
| “我观察到这次侧平举右腕比左腕低，回程比本组常态快” | **Go：可做留出验证后的描述性 beta** | 正面侧平举 52/64 个严格 rep 可对齐；指标是直接图像投影 |
| “我观察到这次正后高位下拉双侧腕高/肘投影角不同” | **Go：可做留出验证后的描述性 beta** | 正后桶 8/8 可对齐；只输出后视二维对称与躯干横移 |
| “这次推肩没有到顶” | **Conditional Go** | 43/44 可对齐，但人工 peak 与腕高极值误差 P90 为 1717ms；先统一顶部事件和机位 |
| “你的动作不标准 / 质量 72 分 / 应该减重” | **No-Go** | 没有专家标准、错误标签、跨人验证或决策阈值；当前规则 `validationSampleSize = 0` |
| “三角肌/背阔肌发力不足、肩胛位置不对、存在受伤风险” | **No-Go，单目 2D 能力边界** | 骨架不观测肌电、外力、被遮挡骨性结构或可靠深度 |

因此目前可以上线的是“**我看到了什么 + 我没看到什么 + 一个可执行但非诊断性的提示**”，不能上线“**你身体里发生了什么 + 你的动作是否正确的总分**”。

## 一手输入与复现范围

本审查只使用项目的一手资产，不重跑视频模型，也不把用户训练动作当作标准动作：

- 人工已审边界：[`data/training/approved-segmentation-v1.json`](../../data/training/approved-segmentation-v1.json)。
- 同一录像的已归档 canonical pose sidecar：[`public/archives/confirmed-captures/`](../../public/archives/confirmed-captures/)。肩部 sidecar 的模型元数据为 `mediapipe:/models/pose_landmarker_heavy.task`。
- 运行时/算法契约：Rust 的 [`normalize_rep_trajectory`](../../rust/motion-sdk/src/lib.rs) 与 [`extract_profile_signal_reference_rep`](../../rust/motion-sdk/src/lib.rs)；它们都从 Rust 已封装 rep 的同一 canonical slice 取样。缺失点保持 `None`，不会被补成另一侧或另一人的点。
- 现有严格高位下拉参考提取器：[`src/pose/referenceTrajectory.ts`](../../src/pose/referenceTrajectory.ts)。它固定为 `16 + 16` 个阶段节点、最近帧距目标不超过 180ms，并明确禁止跨机位比较。
- 机位门控：[`src/pose/viewGating.ts`](../../src/pose/viewGating.ts)。项目本身已把后方机位限定为对称/躯干观察，拒绝纵深轨迹评分。

这不是 MediaPipe 端到端准确率、人体生物力学验证或独立泛化测试；全量样本来自同一位训练者与少量连续采集环境，因此下表仅回答“数据在技术上能否注册到共同相位”。

### 当前代码已经做到与尚未做到的事

- [`PoseEngine.ts`](../../src/pose/PoseEngine.ts) 使用 Pose Landmarker `VIDEO` 模式，检测/存在/跟踪门均为 `0.5`，最多返回 4 个 pose candidate；后续 Rust canonical packet 才负责主体连续性。这里的 `0.5` 是模型/工程门，不是“动作判断有 50% 或 70% 准确率”。
- [`referenceTrajectory.ts`](../../src/pose/referenceTrajectory.ts) 和 Rust [`match_reference_trajectory`](../../rust/motion-sdk/src/lib.rs) 已正确绑定 `exercise + variation + trainingSide + equipment + capturePosition + coordinateSystem + poseModelVersion + feature schema`，拒绝跨机位、跨模型和跨上下文套用参考走廊；缺失节点保持 unknown。
- Rust 的 `TrajectoryMatchEvidence.quality_verdict` 明确在“经过审查的校准队列建立决策策略”之前保持 `None`；当前只计算落在个人观察带内/外的描述证据。这和本报告的 No-Go 结论一致。
- [`formRuleEngine.ts`](../../src/pose/formRuleEngine.ts) 的 `EXPERIMENTAL_THRESHOLDS_V1.status` 是 `experimental`、`validationSampleSize` 是 `0`；“左右幅度差 > 0.25”“躯干漂移 > 18°”也都是 `candidate`，候选规则按代码合同**不得评分**。因此现有 UI 若出现总分或“严重不对称”的确定性结论，会超出代码所记录的证据状态。
- [`PoseEngine.ts`](../../src/pose/PoseEngine.ts) 已把 `worldLandmarks` 注释为 `Pseudo-3D`；[`viewGating.ts`](../../src/pose/viewGating.ts) 的 `torso_lean_3d` 也标为“伪3D实验”，但目前对 front/side/oblique45 全部开放。由于函数把推断的 `z` 直接纳入三维角，这一指标在用同步 3D 参考系统验证前只能留在实验/调试界面，不能参与纠错或分数。

这意味着：工程架构已经具备**安全拒答、上下文绑定和描述性比较**的正确骨架；缺的不是再换一个 DTW 或再调一组阈值，而是参考标准、独立验证与用户学习效果。

## 方法

对每个严格满足 `start < peak < end` 的人工 rep：

1. 在 `start → peak` 与 `peak → end` 各均匀取 16 个时间节点（峰值在两个阶段边界各保留一次，共 32 个节点）。
2. 每个节点只接受距离目标时间不超过 180ms、肩/肘/腕/髋可见度 `≥ 0.5` 的观测；用肩中点至髋中点距离归一化。任何缺失仍为未知值。
3. 对可见节点计算三个**二维代理**：双腕相对肩的垂直位置、双腕横向间距、双侧肘投影角。它们不是三维解剖角。
4. “可技术对齐”定义为：覆盖率至少 80%，最长连续缺失不超过 4 个节点。这个门只评价是否能形成可审计的时间序列，不评判动作标准。
5. 为检查人工 `peak` 与可观测极值是否相符，按动作使用一个预先声明的二维信号（下拉：双腕相对肩高度最大；推肩/侧平举：最小；反向飞鸟：双腕横向间距最大），记录自动极值到人工峰的绝对时间误差。
6. 仅对 32 个节点全可观测的 rep 做留一法、相位受限 DTW 诊断（窗口 4 节点）；特征按该桶的中位数和 10%–90% 范围标准化。**DTW 数值没有质量阈值，也不参与 rep 边界或合格判定。** 这与 Rust 的 `constrained_phase_dtw` 设计一致：它是受限的 shadow diagnostic，禁止作为生产判决或无限制时间扭曲。

## 实测：共同相位是否可建立

| 动作 × 实体机位 | 录像 / 人工 rep | 严格有效边界 | ≥80% 覆盖、可对齐 | 全 32 节点、可作 DTW | 人工 peak 与二维极值：中位绝对误差 / P90 | 受限 DTW：中位 / P90 | 判定 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 高位下拉 × 正后 (`rear`) | 1 / 8 | 8 | 8 | 8 | 133ms / 141ms | 0.267 / 0.318 | **可作后方二维轨迹桶**；仅能比较已定义二维代理 |
| 高位下拉 × 左后45 (`rearLeft45`) | 3 / 20 | 20 | 1 | 0 | 135ms / 172ms | — | **不可比较**；19/20 覆盖不足、18/20 有长缺失 |
| 坐姿推肩 × 正面 (`front`) | 6 / 44 | 44 | 43 | 35 | 651ms / 1717ms | 0.455 / 1.742 | **可建立相位桶，但峰值代理不稳**；不能把顶点偏移解释为发力不足 |
| 侧平举 × 正面 (`front`) | 7 / 65 | 64 | 52 | 39 | 133ms / 200ms | 0.409 / 0.612 | **目前最适合二维对齐实验**；1 个边界本身不严格，另有 10 个覆盖不足 |
| 反向飞鸟 × 正面 (`front`) | 4 / 50 | 48 | 17 | 7 | 381ms / 976ms | 0.990 / 2.145 | **暂不可进入轨迹比较**；2 个边界不严格，29 个覆盖不足、31 个长缺失 |

解释：DTW 是同动作同机位、留一法的**相位路径相似度**，单位是本桶标准化特征距离；不同动作之间不能比较数值大小。它证实“有足够点的 rep 可以被共同注册”，不证明动作正确，也不证明反向飞鸟比侧平举更差。

### 这说明什么

- **侧平举正面**：52/64 个严格 rep 已具备技术上可比的完整相位；人工顶点与二维腕高极值接近。它适合先做“左右腕高差、肩线差、轨迹横向展开、阶段时长”的描述性展示。
- **坐姿推肩正面**：43/44 个 rep 有足够点，但 peak 与腕高极值的长尾误差很大。这里的根因可能是人工标注所选的顶部事件、双手不完全同步、投影/遮挡、或实际停顿；在标注协议明确“top”的定义之前，不应把它变成向心完成度或发力评价。
- **正后高位下拉**：数据质量可支持后方二维相位注册；但它只支持双侧腕/肘的图像投影、对称和躯干横移。不可从后视单目 2D 推出胸椎角、纵深手肘路径或背阔肌激活。
- **左后45高位下拉、正面反向飞鸟**：主要问题不是 DTW 算法，而是大量节点没有同时可见的肩肘腕髋。保留缺失并拒绝比较是正确行为；插值/镜像填满会把“看不见”伪装为“动作稳定”。

## 可观测性分级：直接看到、条件推断、不可可靠判断

| 级别 | 结论类型 | 现有系统能否支持 | 合法输出方式 | 边界 |
| --- | --- | --- | --- | --- |
| **A：直接观测** | 可见腕/肘/肩/髋的图像 `x/y`、相对高度、图像平面路径 | 可以，同机位且所需点可见 | `观察到：右腕在第 9–14 相位节点低于左腕` | 只说明屏幕投影 |
| **A：直接观测** | 二维投影角、肩线/腕线差、躯干横移 | 可以，先声明视角和所需关节 | `观察到：肘投影角与个人已审轨迹带不同` | 不能称解剖学关节角或结构性高低肩 |
| **A：直接观测** | rep 的 `start/peak/end` 时间、两阶段时长 | 边界可靠时可以 | `记录：到顶 640ms，回程 810ms` | 时长不等于控制力、力量或肌肉收缩质量 |
| **B：需条件/校准后推断** | “幅度相对不足”“回程相对加快”“连续偏离个人走廊” | 可以，但只相对同一人/同一上下文的已审参考，且要有独立留出验证 | `相对你本组已确认 rep，本次腕高幅度较小；请下一次抬到与肩同高后复查` | 不能直接外推为负重过大或标准动作 |
| **B：需条件/校准后推断** | 一个预先定义的可见错误标签，例如“侧平举双腕高度差” | 可以，但要有教练标签、冻结阈值、跨人/跨 session 灵敏度与特异度 | `本次出现已验证的左右高度差模式` | 每个动作 × 错误 × 机位单独验证，不能用通用总分替代 |
| **B：需外部传感/模型后推断** | 真实 3D 关节角、地面反作用力、关节力矩、肌骨动力学 | 当前单目 2D 不支持；增加同步多视角、标定与已验证肌骨模型后可研究 | `当前采集配置不支持` | 这将是新的测量产品，不是现有 2D 功能的小改动 |
| **C：单目 2D 不可可靠判断** | 深度方向行程、轴向旋转、被遮挡一侧、肩胛/脊柱细分状态 | 不支持 | `当前机位未观测，建议换机位或重录` | 同一 X/Y 可对应不同 Z，遮挡点可能是模型先验猜测 |
| **C：单目 2D 不可可靠判断** | 单块肌肉激活、“发力到位”、负荷是否合适、疲劳原因 | 不支持 | 不输出结论 | 骨架没有肌电、外力、主观用力或器械重量输入 |
| **C：越界主张** | 受伤风险、诊断、疼痛原因、“动作安全” | 不支持 | 明确拒答并在不适时建议停止/咨询专业人士 | Google 模型卡也说明模型不用于人命攸关决策 |

Google 官方 Pose Landmarker 文档把 `Landmarks.x/y` 定义为按图像宽高归一化的坐标，`z` 以髋中点为原点且量级近似 `x`；`visibility` 是“点在图像中可见的可能性”。文档另提供以米为单位的 `WorldLandmarks`，但这并不代表手机测得了真实深度。[官方 Web API 输出定义](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js#handle_and_display_results)

原因在模型本身：官方模型卡把“需要公制准确深度”列为 out of scope，说明 3D 坐标来自 GHUM 合成人体模型拟合到 2D 投影；隐藏点难以人工定义时会使用 best guess/default pose，光照、噪声、运动、遮脸及极端环境会增加帧间抖动。它还要求单人、居中、完整人体与周围余量，超过约 4 米也超出范围。[BlazePose GHUM 3D 模型卡](https://developers.google.com/static/ml-kit/images/vision/pose-detection/pose_model_card.pdf)

原始 BlazePose GHUM 论文直接指出：从 3D 拟合到 2D 时，同一 X/Y 投影可对应多个合理姿态（不同 Z），所以还需深度顺序标注来减少歧义；论文的 Heavy 3D 误差数字来自特定 yoga/fitness/dance 测试和 GHUM 拟合参考，不是本产品这些动作、机位与遮挡条件下的关节角保证。[Grishchenko et al., 2022](https://arxiv.org/abs/2206.11678)

独立同步实验同样支持“只在视角和关节合适时使用”：15 名参与者的步态研究发现，被遮挡侧髋/膝的误差离散约为可见侧的两倍，正面髋/膝的误差范围占其总活动范围的 35%–46%，踝关节约 ±12°，不足以用于实际判断。该研究不是本产品动作的直接准确率，但验证了当前“缺失即 unknown、不要补点”的策略。[Wade et al., 2023](https://doi.org/10.1371/journal.pone.0293917)

若未来业务确实需要 3D 运动学，技术路线存在，但采集与验证合同会改变。OpenCap 使用至少两台同步手机、相机标定、人体模型和物理仿真；其原始验证研究证明低成本多视角方案可以估计 3D 运动学/动力学，但这不能为当前单目 MediaPipe `worldLandmarks` 背书。[Uhlrich et al., 2023](https://doi.org/10.1371/journal.pcbi.1011462)

## 什么时候才可以说“能帮助纠错”

以下条件必须同时满足；少一项就降级为描述性回放或拒答。

1. **先把产品主张缩成可验证的一句话。** 不是验证“侧平举好不好”，而是逐个验证“正面侧平举中，双腕相对肩高度差是否超过某阈值”“回程是否相对个人基线明显缩短”。一个动作可有多个错误标签，但每个标签都有自己的关节、机位、相位和提示。
2. **上下文完全匹配。** 固定 `exercise + variation + equipment + trainingSide + capturePosition + poseModelVersion + feature schema`；相机翻转、分辨率/FPS、镜头距离与机位容差也要记录。更换模型或机位即视为新版本，旧阈值不能自动沿用。
3. **采集条件可测。** 单人、目标身份稳定；所需关节在画面内；避免器械/躯干遮挡和强逆光；身体居中、全身及余量尽可能完整、距离不超过模型卡边界。对每条反馈必须在 rep 级输出 coverage/最长缺失/置信度；不满足即 `未观测`，不能用插值把失败变成功。
4. **rep 与事件定义可靠。** `start/peak/end` 必须来自同一 canonical slice；每个动作先写清 peak 是“腕最高”“肘最低”“器械触胸”还是“教练认为完成向心”，并验证自动事件对人工事件的误差。对坐姿推肩，这一条件当前未满足。
5. **参考不是用户随便做的一组。** 建立个人走廊前需要用户明确批准，且源 rep 需由合格教练按冻结协议审核；训练数据、阈值调参数据和最终测试视频按参与者/session 隔离。个人走廊只能说明“偏离已确认的自己”，人口标准还需要更大且代表性的参考队列。
6. **系统要会拒答。** 低可见度、长缺失、身份切换、机位不符、动作/器械不符、相位失败或输入超出验证分布时，不给替代答案；提示用户换机位、退远/靠近或重录。
7. **反馈必须具体且能执行。** 一次只提示一个经过验证、用户下一次可改变的外部可见目标，例如“下一次让双腕在顶部接近同高”；不把代理解释成病因，例如不说“右侧三角肌没发力”或“重量太重”。优先在 rep 后反馈，避免实时提示造成注意负担；实时模式需另做延迟和干扰实验。
8. **最后验证用户真的改善。** 在未参与建模的新用户上做随机或交叉实验；比较“有反馈”与“仅回放/无反馈”，测下一 rep 的目标误差、教练盲评、误报造成的反向调整，以及撤掉提示后的保持。只有算法正确而没有行为改善，不能宣传“帮助纠正”。

### 建议的分阶段验证门

下列数字是本项目的**预注册产品门槛建议**，不是 MediaPipe 官方保证或通用生物力学标准；应在看测试集之前冻结，不能为过关事后调低。

| 阶段 | 最低证据与建议通过门 | 未通过时 |
| --- | --- | --- |
| 0. 可观测性 | 目标桶严格 rep 中，所需特征 ≥80% 节点可用、最长连续缺失 ≤4/32；自动 peak 对冻结人工事件的 P90 ≤200ms（仅对需要 peak 精度的反馈） | 改机位/采集/事件定义；不训练分类器 |
| 1. 标注可靠性 | 每个错误标签由至少 2 名独立教练盲标；先定义一致性通过门与仲裁流程，低一致性标签直接删除或改写 | 说明“正确”本身不可稳定定义，No-Go |
| 2. 信号效度 | 在同步人工标点或 3D 参考子集上报告 bias、MAE 和 Bland–Altman limits of agreement；误差必须小于教练定义的最小有意义差异 | 只保留粗粒度描述，不报角度/阈值错误 |
| 3. 错误检测 | 按参与者和 session 隔离的最终测试集；每个错误标签建议 sensitivity ≥0.85、specificity ≥0.90，且 95% CI 下界分别 ≥0.75/0.85；同时报告拒答率 | 不对用户触发该提示；继续 shadow |
| 4. 鲁棒性 | 新设备、距离、衣着、体型、肤色/光照和合理机位偏差分层报告；任一预设组性能下降 >10 个百分点或跌破阶段 3 门即限制支持范围 | 收窄支持环境或补数据重验 |
| 5. 纠错效果 | 随机/交叉用户实验中，反馈组的预注册目标相对对照有实际意义的改善，错误方向调整不增加，并在无反馈保持测试中保留 | 只能称“动作观察/回放”，不能称“纠正” |

阶段 0 的 `80% / 4节点 / 200ms` 直接对应当前 32 节点、约 20fps 的内部实验合同；阶段 3 的灵敏度/特异度门体现“宁可拒答，也不要频繁把正确动作说错”的产品取舍。二者都必须用留出数据复核，不能因为本报告中的同一人回放达标就视为生产验证。

### 自动纠错发布验收清单

- [ ] **数据：** 目标动作 × 错误 × 机位达到阶段 0，且样本覆盖自然正确、自然错误、教练引导错误和不可观测输入。
- [ ] **参考真值：** 至少两名独立教练按冻结协议盲标并完成仲裁；需要角度主张时，另有同步人工标点或 3D 参考验证。
- [ ] **独立留出：** 调参集与最终测试集按参与者和 session 隔离；跨人、跨 session、设备和预设采集条件均达到阶段 3–4。
- [ ] **误报与拒答：** 每个标签达到预注册的 sensitivity/specificity 与置信区间门；同时报告误报率、拒答率和身份/机位/遮挡失败，不用插值隐藏失败。
- [ ] **用户改善：** 随机或交叉实验相对回放/无反馈对照改善预注册目标，错误方向调整不增加，撤掉反馈后仍有保持。

五项全部通过才可称“该动作、该错误、该机位下的自动纠错”；任一项失败都只能保留为动作观察、shadow 提示或明确拒答。

## 对当前产品的明确结论

1. **“轨迹没对齐”里有两类问题。** 对人工边界已正确的侧平举、正后高位下拉，32 节点相位对齐是可行的；问题不在 DTW。对反向飞鸟和左后45下拉，首先是观测缺失；算法不应该对未知点强行对齐。
2. **当前 Rust 的方向是正确的，但产品能力尚未等于“姿态/发力识别”。** `normalize_rep_trajectory` 已做髋中点原点、肩宽尺度、镜像元数据和分相位重采样；`extract_profile_signal_reference_rep` 已保证来自 sealed canonical slice。通用模拟 baseline 目前只暴露 profile 的两个阶段信号，不能替代动作特有的姿态特征。`quality_verdict = None` 应继续保持，直到上述阶段 1–4 通过。
3. **DTW 应仅做诊断。** 允许它随意扭曲时间会把停顿、提前反转和离心过快“对齐掉”。现有 Rust 已把它限制为有窗、shadow-only；应保持这个约束。
4. **现有规则阈值不能用于生产纠错。** `validationSampleSize = 0`、`status = experimental/candidate` 是代码里的真实证据状态；`0.25` 左右差、`18°` 躯干漂移、相对幅度 0.8/0.65 等只能作为待验证假设，不能因为写进常量就变成生物力学标准。
5. **最近可落地的二维质量代理（不带好/坏裁决）**：
   - 侧平举正面：双腕相对肩高度、腕间距、肘投影角、左右肩线差、两个阶段时长。
   - 高位下拉正后：双腕相对高度、肘投影角、双侧差、躯干横移；不包含纵深/背部肌肉结论。
   - 坐姿推肩正面：先显示相位和双侧手腕/肘的观察曲线；先复核人工 `top` 事件定义，后再谈轨迹带。
6. **不要对反向飞鸟做“补点后评分”。** 下一轮采集应按推荐的 `rearLeft45` 机位重新录制，完整保留肩、肘、腕、髋；现有正面数据可以继续服务于计数故障分析，但不应成为动作质量轨迹样本。
7. **伪 3D 躯干倾角先退出纠错路径。** 当前 `torso_lean_3d` 对所有分析机位开放与证据强度不匹配；在同步参考验证前，应只保留同机位趋势研究或直接改用支持机位下的二维躯干投影角。

## 最小下一实验：用最小成本回答“真的能纠正吗”

选择唯一首发标签：`lateral_raise + front + bilateral + 当前 heavy model` 下的“顶部双腕相对肩高度差”。不要同时验证总分、耸肩、肘角和回程速度。

1. 先由 2 名教练写下标签定义、最小有意义差异、正确提示和禁止解释，并独立复标现有视频；只保留一致性可接受的标签。
2. 用现有 52 个可对齐 rep 做算法开发，但按完整录像划分，至少留出整段录像，不允许同一段的相邻 rep 分到训练与测试两边；现有同一训练者数据只用于证明流水线，不能完成阶段 3。
3. 新采集多名未参与建模的用户，每人至少两个 session，包含教练刻意引导的有/无该错误样本和自然训练样本；记录设备、距离、机位偏差、光照与拒答原因。
4. 先做 shadow 检测，达到阶段 0–4 后，进行小型随机交叉试验：一组在 rep 后收到“下一次让双腕在顶部接近同高”，另一组只看回放；比较下一 rep、下一组及撤掉提示后的教练盲评和腕高差。

**实验 Go：** 留出用户上检测门通过，系统能在不可见时稳定拒答，且反馈让目标误差出现预先定义的改善而不增加反向修正。**实验 No-Go：** 标签教练间不一致、跨 session 性能塌陷、误报高、或用户看见提示却没有比回放对照改善；此时应保留“观察曲线”，不要继续调一个动作总分。

在获得教练/专家对参考动作的独立审核、并有跨人/跨采集验证前，页面应继续使用“观察到的差异”“未观测”“需复核”，而不是“正确/错误”“发力不足”或动作质量分数。

## 最终回答

- **现在到底能不能纠错？** 能做有限的、基于二维可见差异的实验性反馈；尚不能证明它真的帮助新用户纠正，也不能发布通用正确性分数。最接近可用的是正面侧平举，其次是正后高位下拉。
- **需要满足什么条件？** 精确动作/机位/模型绑定、所需点稳定可见、rep/peak 可靠、专家定义与审核的单一错误标签、独立参与者/session 留出验证、低置信度拒答，以及随机/交叉用户实验显示反馈后动作确实改善并保持。
- **技术上什么可行？** 二维相对位置、投影角、对称、相位、幅度与节奏的描述和针对性提示可行；可靠 3D 角度、深度路径、负荷/力矩、肌肉激活、疲劳原因和伤病风险在当前单目 2D 配置下不可行。
