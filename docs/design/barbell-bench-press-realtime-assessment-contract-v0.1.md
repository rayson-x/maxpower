# 平板杠铃卧推实时轨迹与训练执行评估契约 v0.1

日期：2026-08-12
状态：research contract；识别链路可做因果回放，标准动作 envelope 尚未完成专家数据验证，不允许 production promotion。

## 结论

系统不能用“与一条理想骨架逐帧相似”来判断卧推标准度。正确做法是同时维护四层、互不覆盖的证据：

1. **实际轨迹**：每帧 canonical 人体点、杠轴/器械点、质量、时间戳和 unknown 状态。
2. **动作阶段**：准备位、下放、实际最低点、推起、返回端点与封装 rep。
3. **参考 envelope**：同一平板杠铃卧推变式、训练意图和机位下，经审核的可接受特征范围；不是单一教练的一条轨迹。
4. **教练推断**：只有持续的多特征偏差超过观测噪声后，才输出一条条件化建议；预测值不得回写覆盖实测值。

机器可读契约位于 `configs/training-execution/barbell-bench-press-flat-standard-front-v0.1.json`。

## “标准卧推”在本产品里的定义

默认合同是：平凳、杠铃、双侧、计划可用全程、以技术或增肌为目的、受控下放、底部平稳换向、完整推回。力量举停顿、touch-and-go、刻意 partial、窄握/宽握、特殊 tempo、上斜/下斜都必须显式切换合同，不能共用同一标准阈值。

标准执行首先是可重复完成以下任务：

- 准备/返回端点稳定；
- 下放阶段杠铃连续下降，左右肘发生对应屈曲；
- 到达本次实际最低点并发生可确认反向；
- 推起阶段杠铃连续上升，左右肘发生对应伸展；
- 回到计划端点后才封装 rep；
- 杠铃左右端、腕肘路径和反向时序在该变式允许范围内；
- 支撑和躯干没有出现本机位可见、持续且与相位相关的异常漂移；
- 后半组的 ROM、路径、节奏与双侧协调变化被单独描述，不自动归因“肌肉没力”。

它不要求所有人的绝对角度或杠路完全一致。握距、胸廓、臂长、拱背策略、训练目的、负重和疲劳都会改变合法轨迹，因此参考数据必须学习“可接受走廊”，不是一条平均曲线。

## 当前正面脚端机位能看什么

| 维度 | 当前可做 | 当前不能可靠做 |
| --- | --- | --- |
| Rep/阶段 | 下放、最低点、推起、返回和计次 | 把屏幕上下方向直接当成肌肉向心/离心而不经过动作语义 |
| 双侧 | 腕肘反向时差、ROM 差、杠端高度变化、动态倾斜 | 真实左右力量差、肌肉激活差 |
| 杠铃 | 杠轴中心、端点、斜率、逐帧路径 | 没有盘片/轴真值时声称精确 3D 杠路 |
| 支撑 | 可见肩线、髋/躯干整体漂移代理 | 肩胛后缩/下沉、腹压、胸椎和脊柱状态 |
| 底部 | 视觉最低点与换向控制 | 在身体/杠接触证据不可靠时断言是否触胸 |
| 训练效果 | 描述路径、控制和组内退化，给条件化提示 | 实际力、关节力矩、伤病风险或刺激百分比 |

正面脚端更适合左右协调。若要判断杠铃相对胸部的前后路径、触点与肘—腕在矢状面的关系，应增加侧面或验证过的 45° 机位；不能让一个机位承担所有判断。

## 实时预判如何工作

预判只读当前和过去帧：

```text
实测帧 → 因果滤波 → 当前 phase 概率
                    ├─ 下一阶段时间窗
                    ├─ 预计最低点/返回端点范围
                    └─ 预计可接受轨迹走廊
                              ↓
             持续偏离且观测可靠 → 一条实时 cue
```

- 最低点不能在最低点当帧“确定”，因为确定方向反转至少需要后续一至两帧；输出必须同时保存 `turnaroundMs` 与 `confirmedAtMs`。
- 可以先输出 `predicted_bottom_window`，在真正反转后改为 `measured_turnaround`，但两者的 provenance 必须不同。
- 标准参考帮助缩小下一阶段的合理走廊，不能替代丢失点，也不能把预测骨架画成实测骨架。
- 腕肘骨架与可靠杠铃轨迹冲突时，不能选择更符合“标准姿势”的一方来补造事实；该维度进入复核或 `cannot_judge`。
- 实时只给最高优先级的一条提示；完整轨迹、各维度变化和证据留到训练后复盘。

## 参考数据分层

现有 6 条个人卧推视频与 46 次人工确认最低点适合训练/验收计次和阶段，但用户已明确这些动作并非标准，因此不得把它们直接训练成标准动作。

参考数据库应分成：

1. **理论 prior**：决定观察哪些特征和哪些因果结论禁止输出，不直接给数值阈值。
2. **教练审核 standard envelope**：多名熟练者、多体型、多负重和自然合法路径；按机位、变式和意图分桶。
3. **普通用户合法变化**：控制 clean-set 误提示。
4. **单一/组合偏差**：ROM 不足、左右时差、反弹、回程失控、器械路径漂移、组内退化等，保留替代解释。
5. **个人稳定基线**：只比较这个用户本组/历史的一致性，不自动等于“正确”。

首轮偏差标注无需逐帧重画骨架。系统先自动生成 rep 级特征，审核者只需确认“可见事实、是否有意、是否应提示、主要 cue”；争议样本进入仲裁。

## 验收

识别和教练质量分开验收：

- 识别：rep precision/recall、最低点误差、确认延迟、start/end 边界、错误计次；
- 轨迹：人体与器械覆盖、跳变、identity switch、设备 FPS/延迟/丢帧；
- 标准度：每个偏差 pattern 的 precision/recall、clean set false cue、cannot-judge、提示延迟和专家一致性；
- 泛化：participant × session × source video × device 分组留出；同视频回放不能称为陌生视频准确率；
- 表述：不得输出左右真实发力、肌肉激活、关节力矩或伤病结论。

当前能力入口：`docs/reports/current-barbell-bench-recognition.md`。它回答 Web 单次因果链路中的杠铃轨迹、骨架观测与 Rust 阶段输出是否对齐；真正实时产品仍必须把同一接口接到摄像头，并在 Android/iOS/Web 上记录端到端时间与掉帧。
