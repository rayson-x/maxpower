# MaxPower 产品文案系统 v1

## 目标

MaxPower 的文案应该像一位克制、可靠、懂训练的搭档：说人话，先告诉用户现在发生了什么，再给出下一步。界面不展示工程实现、模型名、内部状态码或数据结构。

## 语气

- **直接**：标题描述用户任务，例如“本组记录”，不用“统一训练执行”。
- **克制**：不夸大能力，不用“智能识别一切”一类承诺。
- **有行动性**：错误和空状态必须说明用户接下来能做什么。
- **不评判**：摄入、训练完成度和动作观察陈述事实，不羞辱、不制造焦虑。
- **统一称谓**：产品助手统一叫“Coach”；其余内容使用中文，不做无意义的中英混排。

## 信息层级

1. **页面标题**：用户来这里做什么，如“我的计划”“训练记录”。
2. **当前状态**：正在发生什么，如“进行中”“等待确认”。
3. **证据或原因**：为什么得到这个状态。
4. **下一步操作**：按钮使用动词 + 对象，如“开始训练”“保存本组”。
5. **边界说明**：只在影响信任或安全时出现，并尽量短。

## 词汇表

| 内部或旧文案 | 产品文案 |
| --- | --- |
| Canonical observation | 相机观察 |
| exact profile / profile | 支持自动计次 / 暂不支持自动计次 |
| Realtime | 相机计次 |
| Session | 训练 |
| Timeline | 记录 |
| Set Review | 本组记录 |
| confirmed Result | 已同步训练结果 |
| RIR | 剩余次数（首次出现可保留 RIR 解释） |
| PLAN CHECK READY / REBUILD READY | 有调整待确认 / 新计划待确认 |
| ACTIVE PROGRAM | 当前计划 |

## 状态与错误模板

- 加载：`正在 + 动作`，例如“正在读取训练记录…”
- 成功：`对象 + 已 + 结果`，例如“训练视频已保存”
- 可重试错误：`暂时无法 + 动作。请重试。`
- 需要授权：先说用途，再给操作，例如“允许联网后，Coach 才能继续分析。”
- 冲突：说明数据没丢，再要求刷新，例如“内容已更新，你的记录仍保留。刷新后再试。”
- 空状态：说明价值和第一步，例如“还没有训练记录。完成一次训练后，这里会显示趋势。”

## 禁止项

- 不直接展示错误码、下划线 token、JSON、模型或运行时名称。
- 不在面向用户的标题中使用 `canonical`、`profile`、`packet`、`revision`、`provider`。
- 不把“未记录”写成零，也不把模型推断写成用户事实。
- 不用真实用户资料、精确身体数据或行为习惯做 placeholder；未填写的输入保持为空，主观评分必须由用户主动选择。
- 示例只说明“该填什么”，不暗示“用户是什么”；测试或演示数据不得进入正式界面的默认值和提示文案。
- 同一屏不混用“确认 / 接受 / 应用 / 启用”表达同一个动作。

## 按钮规则

- 主按钮描述立即结果：`保存本组`、`确认计划`。
- 次按钮描述替代路径：`稍后再说`、`继续修改`。
- 避免“处理”“应用”“完成”等缺少对象的孤立动词。
- 删除操作必须点明对象，并在确认层说明影响范围。

## 维护规则

- 领域层只输出结构化 code；用户文案留在客户端。
- 新页面提交前检查四类文案：正常、空、加载、错误。
- 新错误码必须先映射成用户可读文案；没有映射时显示场景兜底，不显示原码。
- 中英文资源应使用相同 key；新增中文文案后补齐英文权威源，逐步把散落字符串迁入 `src/i18n/translations.ts`。
