# 骨架 + 器械双通道识别与左右不对称证据（v0.1）

日期：2026-08-11  
范围：识别能力规划。不修改生产代码，不替换现有 MediaPipe 骨架链路。

## 目标能力

同一帧内并行获得人体骨架与器械观测，由 Rust 融合后输出**左右不对称的几何证据**，用于卧推、推举、划船等双侧动作。

## 首先要区分的两件事

这条能力最大的风险不是技术，是表述。

| | 可观测 | 不可观测 |
| --- | --- | --- |
| 杠铃左右端高度差、倾角、随时间的变化 | ✅ 刚体几何事实 | |
| 左右哑铃的高度差与时间滞后 | ✅ 轨迹事实 | |
| 肩线倾斜、左右肘角差 | ✅ 骨架几何 | |
| **"左边发力不足"** | | ❌ 力不可见 |
| 肌肉激活、代偿模式、损伤风险 | | ❌ 超出 2D 可观测范围 |

杠铃倾斜是**观测**，两边发力不同是**推断**。同一个倾角可以来自发力不均、握距不对称、胸椎旋转、配重不等或器械本身。

PRD 的 Out of Scope 已经写明「从 2D pose 推断实际重量、RIR、疼痛原因、肌肉激活、伤害风险或真实 3D 生物力学」不在范围内。本能力必须落在**观测侧**，沿用高位下拉参考轨迹已经确立的模式：输出描述性证据，`qualityVerdict` 保持 `null`，只测量不下结论。

产品上正确的表述是「杠铃右端在向心段后半程比左端低 3.2°，本组 8 次中出现 6 次」，而不是「你左边发力不足」。原因假设可以由 Coach 以候选形式提出，并请用户确认，但不能作为系统判定写入事实。

## 架构

```text
同一帧 RGB
  ├─ MediaPipe Pose Landmarker（全帧，stream 模式）→ 33 点骨架
  │     └─ 内部 ROI 回环与时序跟踪保持不动
  └─ YOLOX-nano（间隔帧）→ 杠铃片 / 哑铃 / 杆轴段观测
        └─ 帧间 Kalman / 稀疏光流补点
                    ↓
        Rust：主体锁定 → 器械轨迹锁定 → 手-器械关联
                    ↓
        左右不对称证据（描述性，不含因果结论）
```

两条链路在时间轴上解耦，互不污染。

**为什么不把 YOLOX 的框喂给 MediaPipe**：MediaPipe 底层 `PoseLandmarkerGraph` 虽然声明了可选的 `NORM_RECT` 输入，但公开 Tasks API 显式拒绝 `region_of_interest`，会返回 invalid argument。更重要的是，MediaPipe 在 stream 模式下依赖上一帧 pose rect 做回环，逐帧变化的裁剪窗口会破坏这个时序状态，等于退化为逐帧全量检测。详见 [`2026-08-11-pose-framework-comparison.md`](../research/2026-08-11-pose-framework-comparison.md)。

**为什么器械可以间隔帧**：器械是刚体、运动连续。rtmlib 的 `PoseTracker` 已经验证了这个模式 —— `det_frequency` 控制检测间隔（官方示例用 10），其余帧复用上一帧框，配合 IoU 关联维持身份，`tracking_thr` 默认 0.3。

## 不对称信号：按抗透视鲁棒性排序

透视是这条能力的头号威胁。**相机不垂直于杠铃轴时，水平的杠铃在画面里就是斜的。** 因此信号设计必须优先选择对固定机位误差不敏感的量。

### 一级：时间不对称（最鲁棒）

左右两端到达顶点/底点的时间差，或一侧在向心段的滞后。

**时序是投影不变量** —— 固定机位带来的角度偏移不影响「谁先到顶」。这是唯一不需要标定就成立的信号，应作为首个落地目标。

哑铃场景尤其适用：两个独立刚体没有共同轴，但左右轨迹的时间滞后是干净可测的。

### 二级：动态偏差（次鲁棒）

倾角在一次 rep 内的变化量，而非绝对倾角。

固定机位的透视误差在一次 rep 内近似恒定，做差即可消去。报告「顶点与底点之间倾角变化 4.1°」比报告「倾角 6.3°」可信得多。

### 三级：绝对倾角（需标定）

必须先建立水平基准，两种可行方式：

1. **架上标定**：组开始时杠铃在架上，视为已知水平，记录此时的表观角度作为零点，之后只报告相对该基准的偏差。前提是杠铃确实在画面内且架子本身水平；哑铃无此参照。
2. **全组中位数基准**：以本组倾角中位数为零点。代价明显 —— 若用户**持续**单侧偏低，这个偏差会被一起归一化掉，恰好抹掉了要测的东西。因此它只能用于检测组内变化，不能用于检测恒定不对称。

> 边界：广角镜头在画面边缘会把直线弯曲，靠近边缘的杠铃倾角不可信。首版应要求器械位于画面中央区域，或在证据中标注「靠近边缘，倾角不可比」。

## 器械观测的优先级

沿用 [`2026-08-09-barbell-dumbbell-equipment-detection-tracking.md`](../research/2026-08-09-barbell-dumbbell-equipment-detection-tracking.md) 已确立的证据优先级，不重新设计：

1. 左右**动态杠铃片中心**、半径与同步轨迹（杆细且与机架重叠，杠铃片更明显、运动更稳定）
2. 可见的杠铃轴段及方向
3. 骨架手腕到杆轴的投影握点
4. 肩点、骨长与时间连续性约束恢复的肘点

静态挂片、镜中杠铃和他人器械不能仅凭检测分数过滤，必须结合「与已锁定主体手腕的距离 + 左右同步运动 + 当前动作阶段 + 轨迹连续性」关联。证据二义时输出 `Unknown`。

## 前置条件

**Rust profile contract 目前写死 BlazePose33**（见 [`current-capability-audit-2026-08-04.md`](../reports/current-capability-audit-2026-08-04.md)）。器械观测不是 BlazePose 拓扑里的点，无法作为新的 landmark 源注入。

因此第一步不是训 detector，而是**把关键点拓扑参数化**，让 Rust 能同时接受：

- BlazePose33 人体点（Measured）
- 器械几何点（杠铃片中心、杆轴端点、哑铃中心）
- 由约束 IK 反解的点（Predicted）

`CanonicalLandmark(Measured/Fused/Predicted/Unknown)` 已经是正确的抽象，缺的是拓扑不再硬编码。

这一步同时解锁 RTMPose 作为 A/B evaluator 接入 —— 是所有识别路线的共同瓶颈。

## 分阶段路线

每阶段以一个可证伪问题结束，不通过就不进入下一阶段。

**阶段 0 · 契约参数化**  
Rust profile contract 支持可变关键点拓扑。  
验证：同一段视频可同时装载 BlazePose33 与一个器械几何 profile，互不干扰。

**阶段 1 · 时间不对称基线（不需要 detector）**  
用已有的 bar-axis 原型信号，先只回答：左右两端的时间滞后是否在标注语料上稳定可测。  
验证：在 6 条已标注卧推视频上，滞后量在同一人同一组内的方差小于组间差异。不成立则这条信号不存在，及早停。

**阶段 2 · 器械 detector**  
训练 RTMDet-tiny 或 YOLOX-nano（均为 Apache-2.0）输出杠铃片 / 哑铃 / 杆轴段。  
验证：在 out-of-sample 视频上，杠铃片中心检出率与轨迹连续性达到门槛；**必须是样本外**，第一轮 bar-axis 的 46/46 是 in-sample tuned 结果，不可复用为通过证据。

**阶段 3 · 移动端预算**  
测量目标 Android 机型上 YOLOX-nano 单帧延迟，确定 `det_frequency`。  
验证：MediaPipe 全帧 + YOLOX 间隔帧的合计延迟在 30fps 预算内，且降采样敏感性可接受。第一轮验证已暴露该风险：15fps 下 46/46，10fps 降为 45/46，270×480 多出 4 个额外周期。

**阶段 4 · 不对称证据产品化**  
按既有 `动作 × 变式 × 器械 × 机位` 口径逐组验证，接入 SetAssessment。  
验证：证据表述通过诚实性审查 —— 不出现任何力、肌肉或损伤的因果断言。

## 明确不做

- 不替换 MediaPipe 作为人体关键点来源（BlazePose33 contract 与全部已训 profile 绑定）。
- 不使用 Ultralytics YOLO（AGPL-3.0，权重同授权）。器械 detector 用 RTMDet-tiny 或 YOLOX-nano。
- 不从倾角推断力、肌肉激活或损伤风险。
- 不在阶段 2 通过前，把任何器械信号注入 Rust 正式计数。
