# AI 教练：训练目的—执行特征—偏差—影响—提示矩阵 v0.1

**Status:** Product knowledge contract / requires exercise-level review and validation  
**Date:** 2026-08-09

## 1. Why this matrix exists

AI 教练不应从“某个角度超过阈值”直接跳到“动作不标准”。判断链必须完整：

`当前训练目的 → 该变式的标准执行特征 → 持续可见偏差 → 可能的运动策略/刺激影响 → 可执行提示`

同一个外观在不同训练目的下可能有不同含义。力量举卧推中的停顿要求、增肌训练中的受控离心、爆发动作中的主动加速，不能共享一个“标准节奏”。本文件定义跨动作可复用的知识模式；具体动作是否启用、用什么特征和机位，在动作映射中另行声明。

## 2. Evidence roles

每个动作的标准执行特征必须按角色建模，而不是全身逐点相似度：

| 角色 | 含义 | 典型证据 |
|---|---|---|
| Defining active feature | 构成动作任务的主要可见变化 | 肘屈伸、膝屈伸、髋位移、腕/器械相对躯干路径 |
| Stable/support feature | 完成主动运动时应大致保持的支撑或姿态 | 俯身角、骨盆水平、上臂位置、足部支撑、凳面接触代理 |
| Endpoint/ROM feature | 是否到达并离开关键端点 | 最小/最大关节投影角、相对高度、触及/接近位置 |
| Phase-control feature | 向心、离心、停顿和反转的可见时序 | 方向变化、阶段时长、端点停留、回程连续性 |
| Bilateral/coordination feature | 两侧或多肢段之间的同步关系 | 左右端点差、相位差、路径差、手脚开合同步 |
| Equipment-path feature | 仅靠人体骨架不足时的外部约束 | 杠铃轴线、哑铃/把手、机器连杆、凳面和支撑点 |

“向心/离心”不是屏幕中的上升/下降。它由 exact exercise profile 中目标动作与负荷方向的关系定义。普通单目骨架可识别阶段和运动方向，但不能直接证明肌纤维行为、力矩或实际肌肉激活。

## 3. Training-purpose matrix

| 训练目的 | 标准执行关注点 | 常见偏差模式 | 可能的实际影响 | 优先教练提示 |
|---|---|---|---|---|
| 技术学习 / 动作熟练 | 可重复路径、清晰端点、稳定支撑、低变异、可控阶段 | 路径漂移、动作定义变化、连续试探、左右交替失序 | 难以形成稳定动作策略，也让后续负重与进步不可比较 | 先简化成一个可重复任务；给一个外部注意焦点 |
| 肌肥大 / 局部训练 | 目标关节有效 ROM、受控回程、稳定支撑、合理接近力竭 | 行程缩短、惯性借力、支撑段参与增多、回程坠落 | 可能减少目标关节在预期区间的机械需求，或把需求转向其他关节动作 | 保持支撑，再完成目标关节行程；必要时减重 |
| 最大力量 / 力量技术 | 可复现设置、符合规则的端点、器械路径、整体张力与动作成功 | 起始设置漂移、关键端点缺失、杠路偏移、左右不同步、粘滞点策略崩解 | 可能降低动作效率或使本次 rep 不符合所选技术/规则标准 | 恢复设置与路径；提示最关键的一个技术锚点 |
| 爆发力 / 功率 | 明确准备、主动加速、协调传力、完整减速/复位 | 准备不足、肢段时序脱节、速度目标消失、落地/复位不稳 | 可能降低外部动作速度或传力效率；视频只能观察运动学表现 | 先稳定准备位，再“快而完整”；速度必须有外部测量才量化 |
| 肌耐力 / 容量 | 合法 rep 持续性、节奏一致、行程保持、技术衰减趋势 | 后半组 ROM 缩短、节奏失控、代偿增多、停顿变长 | 可能表明执行策略随疲劳改变；不能仅凭视频归因于某块肌肉疲劳 | 保持同样行程；若连续失守则结束或降级 |
| 控制 / 慢离心 / 停顿 | 指定阶段时长、端点控制、无反弹、其余结构稳定 | 过快回程、端点反弹、停顿消失、用其他关节抢回程 | 训练任务本身未被完成，预期的阶段暴露时间减少 | “回程再慢一点”“停稳后再启动”，按契约提示 |
| 单侧 / 平衡能力 | 工作侧任务、骨盆/躯干控制、支撑稳定、重复一致 | 骨盆侧移、躯干侧倾、左右节奏/ROM 差、支撑脚漂移 | 可能通过改变身体位置和力臂来完成任务；不能等同“弱侧发力不足” | 描述可见差异，并让用户对齐端点/节奏或降低难度 |

## 4. Reusable deviation-effect patterns

下列模式是知识模板，不是运行时阈值。每个模式必须在具体动作上配置 phase、required features、反例、持续时间和 cue family。

| ID | 标准执行特征 | 持续偏差模式 | 可见证据组合 | 可能的运动策略 / 刺激影响 | 教练提示模板 | 关键替代解释与拒答条件 |
|---|---|---|---|---|---|---|
| `ROM_DEFICIT` | 定义动作的主动关节到达审核端点并返回 | 多次 rep 的目标关节行程持续不足 | 目标角度/相对位移未达个体或变式 envelope；周期仍完整 | 任务可能只完成部分行程，预期区间的机械需求减少 | “再完成一点【目标关节/器械】行程” | 有意部分 ROM、器械限位、镜头投影、身体比例；未声明标准变式则不判 |
| `MOMENTUM_BORROWING` | 支撑段稳定，主动关节主导相位变化 | 主动段启动前或同时出现躯干/髋的明显反向—正向摆动 | 躯干角/髋位移先变，随后目标关节快速完成；跨多 rep 重现 | 更像用惯性和额外关节动作完成任务，可能降低目标关节在该段的相对贡献 | “先稳住【躯干/髋】，再用【目标动作】完成” | 爆发/允许借力变式、相机移动、最后 rep 的一次偶发调整 |
| `TRUNK_STRATEGY_DRIFT` | 该变式要求躯干保持在审核区间 | 躯干俯仰或侧倾随主动相位系统变化 | 肩—髋轴角与相位相关；目标肢段路径同时改变 | 身体位置和力臂改变，可能将机械需求转向另一关节动作或肌群组合 | “保持【俯身/躯干】角度，再完成动作” | 某些变式本就允许躯干运动；单目深度旋转或髋点遮挡时拒答 |
| `SUPPORT_DRIFT` | 足、骨盆、凳面或上臂等支撑关系稳定 | 支撑点滑动、骨盆抬离/旋转、上臂随动 | 支撑点相对位移 + 主动特征异常；必要时结合物体检测 | 稳定约束变化，用户可能通过改变基底或力臂完成 rep | “固定【支撑点】，再做同样行程” | 相机抖动、软垫压缩、支撑物不可见；不能仅靠骨架宣称关节稳定性 |
| `BILATERAL_ENDPOINT_GAP` | 双侧同时或在允许时序内到达相近端点 | 一侧持续较低、较短或提前反转 | 左右 phase-normalized 端点/ROM 差，且两侧 landmarks 均可靠 | 可见执行不对称，可能改变两侧动作任务；不能推断力量或激活差 | “让左右【手/肘/膝】到同一终点” | 斜机位投影、单侧变式、器械不对称、解剖差异；输出“可见差异” |
| `BILATERAL_TIMING_GAP` | 双侧按动作要求同步或按既定交替顺序 | 一侧持续提前、滞后或提前回程 | 左右 phase onset、端点时间和 reversal 差 | 协调策略偏离所选变式，可能使一侧承担不同阶段任务 | “两侧一起启动/到顶/回程” | 交替动作、自然小差异、丢点；不可表述为一侧发力慢 |
| `RETURN_CONTROL_LOSS` | 返回阶段连续、方向一致并符合目标 tempo | 回程速度突增、轨迹跳变或失去阶段控制 | return duration 缩短、速度峰值/jerk、端点到起点近似坠落 | 所选慢回程/受控变式未完成；可能减少回程阶段的可控暴露 | “把回程控制住，再开始下一次” | 设备抖动、低帧率、弹力器械回弹；不能声称离心肌力不足 |
| `REVERSAL_BOUNCE` | 在端点完成审核停顿或平稳换向 | 未到端点即反转，或端点出现快速反弹 | endpoint dwell 缺失、速度未接近零、方向瞬变 | 停顿/受控换向任务未完成，惯性或弹性可能参与更多 | “到终点停稳，再启动下一阶段” | 标准变式不要求停顿、伸缩复合动作、有意 touch-and-go |
| `TEMPO_MISMATCH` | 各阶段落在当前 intent 的宽容节奏范围 | 某阶段持续过快/过慢或组内节奏漂移 | phase duration 与个人/变式 envelope 偏离并持续 | 执行剂量与所选 tempo 不一致；不能单独证明疲劳或训练效果优劣 | “按【下放/推起】节奏完成” | 无 tempo 目标时只描述，不纠错；帧率/时间戳异常拒答 |
| `JOINT_STRATEGY_SUBSTITUTION` | 目标关节变化为主，辅助关节在允许范围 | 目标关节 ROM 缩短，同时另一关节/躯干 ROM 增大 | 两个以上 phase-aligned 特征呈稳定互换关系 | 用户仍完成外部位移，但运动策略改变，机械需求可能偏离训练意图 | “减少【代偿动作】，把行程留给【目标关节】” | 多关节动作的正常协调、特殊变式、不同人体比例；需动作级专家规则 |
| `EQUIPMENT_PATH_DRIFT` | 器械沿该变式可接受路径运动 | 杠/哑铃/把手偏离参考走廊或左右倾斜 | 物体轨迹 + 人体锚点 + 相位；不能只用腕点冒充杠路 | 可能改变力臂、动作效率或目标关节任务 | “让【器械】回到【身体锚点】上方/附近” | 必须有可靠器械检测；自由重量个体路径不可用单一模板硬套 |
| `SEGMENT_ALIGNMENT_DRIFT` | 特定肢段在所选变式维持审核相对关系 | 肩—髋—踝、膝—脚或上臂—躯干关系持续偏离 | 多点相对角/距离，在目标 phase 持续 | 可能改变身体整体传力或支撑策略 | “让【三个锚点】重新对齐” | 不能从投影线直接推断脊柱形态、肩胛位置或损伤风险 |
| `COORDINATION_SEQUENCE_ERROR` | 多肢段按审核顺序打开、关闭或传力 | 手脚/髋膝/拉推顺序错误或失序 | 多 feature onset/peak/reversal 顺序 | 动作任务可能完成，但协调目标未完成或效率下降 | “先【A】，再【B】”或“一起打开” | 动作存在多种合法策略时只按明确 intent 判断 |
| `SET_EXECUTION_DRIFT` | 同组合法 reps 的行程、路径和节奏大致可重复 | 后半组连续出现 ROM、速度、支撑或对称性漂移 | 同一人的 rep-to-rep trend，多维同时变化 | 表明执行策略随组进程改变；可提示减重/停止，但不能归因某肌疲劳 | “后几次行程在缩短；保持标准或结束本组” | 有意递减组、partials、rest-pause；需要用户负重与计划上下文 |
| `ACTION_OR_SETUP_MISMATCH` | 当前动作、器械、侧别与 intent 相符 | 实际执行更像另一动作/变式，或机位无法分析关键面 | 动作分类证据、设置元数据和关键 feature 都不匹配 | 任何后续“标准度”比较失去语义 | “确认动作/凳角/机位后再开始” | 分类置信度不足时不擅自改动作标签，交给用户确认 |

## 5. How phases relate to coach inference

每个动作 profile 必须显式定义：

- 从准备位到负荷方向运动的阶段；
- 目标肌群通常发生缩短/伸长的**预期相位含义**；
- 实际可观察的运动学代理；
- 可判断的稳定特征；
- 关键端点与允许的变式。

例如标准俯身杠铃划船中，侧面或 45° 机位可观察“肘屈/肩后移、器械接近躯干、躯干角相对稳定”。若躯干先明显直立、随后杠铃靠近，则可匹配 `MOMENTUM_BORROWING` 与 `TRUNK_STRATEGY_DRIFT`，并推断“更可能增加上背/斜方及髋躯干参与，使动作偏离标准俯身划船”。这仍不是直接测量背阔肌或斜方肌激活。

## 6. Cue design rules

- 描述用户能控制的外部动作，不使用解剖学羞辱或危险措辞。
- 一次只纠正一个最高优先级问题。
- 先说可执行改变，再在报告中解释原因。
- 提示必须短于实时 UI 可读/可听窗口；详细证据留在 rep 报告。
- 同一提示需要持续证据、最小播报间隔和恢复条件。
- 如果更可能是负重过大，允许提示“减轻重量后保持行程”，但只有在用户输入了负重或连续组内漂移时才这样解释。
- “左右不一致”不得改写为“弱侧没发力”；“躯干变化”不得改写为“核心无力”。

## 7. Review and release gates

每个 `exercise × intent × view × deviation pattern` 是独立发布单元。它必须经过：

1. 健身/运动知识审核：标准变式、合法替代策略和可能影响是否合理。
2. 可观测性审核：手机机位是否真实看得见所需特征。
3. 数据审核：标准、偏差、反例、意图变式和 cannot-judge 样本是否齐全。
4. 标注一致性审核：教练之间是否能可靠复现标签。
5. 模型/规则验证：按 subject/session/device holdout 报告事件 precision/recall 与 clean-set false cue rate。
6. 产品文案审核：没有越过证据等级。

## 8. Non-claims

本矩阵不支持从单目视频直接输出：肌肉激活百分比、左右力量差、关节力矩、组织负荷、疲劳原因、疼痛归因、损伤风险、康复建议或医学诊断。
