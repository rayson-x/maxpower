# 09 — 建档中断、冲突、过期与幂等恢复

**What to build:** 用户在对话、表单、确认和首次规划任一阶段遇到 App 重启、模型断流、工具失败、云端失败、并发修改或冲突输入时，都能恢复到真实状态，不重复写入、不丢证据，也不错误声称已保存或已生成。

**Blocked by:** 08 — 首次 Planner 交接与独立计划确认

**Status:** wontfix

- [ ] 对话捕获、表单提交、档案确认和计划确认均有稳定幂等键；断流重试不会追加重复事件或资源。
- [ ] 新旧字段冲突并列保留来源并要求解决；解决采用 superseding event，不删除或静默覆盖原始证据。
- [ ] 旧 card/catalog revision、旧 draft confirmation 和旧 plan proposal 被明确拒绝为 stale，并给用户可操作的更新或重新确认入口。
- [ ] LLM ToolResult 失败或断流时，Agent 不得输出“已填写”“已保存”“档案完成”或“计划生成成功”等与真实状态不符的文案。
- [ ] ProductData 暂时不可用时保留本地草稿、确认意图和重试上下文；恢复后同一操作只产生一组正式资源。
- [ ] App 重启能恢复正在填写的动态卡片、explicit unknown、未解决冲突、待确认摘要和待确认计划，并保持账号隔离。
- [ ] 全链路审计能从失败/恢复后的结果回溯到触发消息、草稿版本、工具结果和用户确认，不保存 Chain of Thought。
